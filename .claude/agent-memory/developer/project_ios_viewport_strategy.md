The `.app-shell` viewport-fill strategy in src/styles.css is **floor the shell on the STABLE small viewport**:
`min-height: 100vh; min-height: 100svh;` (100vh legacy fallback first) with the existing `overflow: hidden`. Same cascade on `html`/`body`/`#root`. Do NOT add `height: 100lvh` and do NOT end the cascade on `dvh` — both were tried and regressed (see why below). `.decision-sheet` padding-bottom uses `max(10px, calc(env(safe-area-inset-bottom) - var(--sheet-safe-trim)))` where `--sheet-safe-trim: 16px` — a deliberate half-home-indicator trim that fixed a real "too much dead whitespace" complaint (commit d7eac6a); the `max(10px,…)` guard keeps it safe.

**Why svh, not dvh/lvh (measured on iPhone 15 standalone):** `lvh = 852` (full screen incl. chrome) over-fills by ~59px and CLIPS the Open-Meteo attribution (real content) → rejected. `dvh == svh == 793` at rest, but `dvh` is the *dynamic* unit: iOS can resolve it larger during the standalone cold-launch animation and reflow after first paint → the "bottom whitespace too high on COLD start, correct after reopen" bug (2026-06-13). `svh` is the stable floor that never grows after first paint → dimensionally identical at rest, immune to the flicker. Earlier dead ends: `position:fixed; inset:0` (regressed iPhone 15) and JS `--app-height` from `window.innerHeight` (deleted `src/lib/appHeight.ts`, under-reported the home-indicator band). Do NOT reintroduce any of those.

**How to apply:** the desktop `@media (min-width: 720px)` block sets explicit `height: 932px; min-height: 932px` on `.app-shell` and MUST override the mobile fill (same specificity, later in source order — keep it after the base rule); keep its comment honest about the actual base unit (100vh/100svh). Reserve `dvh` for INTERNAL proportions only (`clamp(…,40dvh,…)` hero floor, `calc(100dvh - 56px)` settings sheet), never the outer fill. Before judging any iOS layout change on device, confirm the version line in Settings → "Diagnostiek" matches the build you shipped — a stale service worker masquerades as a device difference. The Diagnostiek block (SettingsPanel.tsx) reads live innerHeight/screen/visualViewport + dvh/svh/lvh/safe-area probes AND a cold-launch capture (src/lib/coldLaunchViewport.ts samples the units at rAF/+500ms/visualViewport-resize) so first-paint transients are visible after the fact. It is intentionally shippable so the user can report real device values.
